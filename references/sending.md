# 微信发送使用与限制

发送前必须完成 [微信skills 的强制草拟与人工审核](../SKILL.md#强制草拟与人工审核)。本文是同一个 skill 的发送模块参考。

发送模块调用独立原生组件，不点击界面、不模拟键盘、不切换前台、不更换微信版本。
当前状态：本机运行地址、文本对象构造和一次用户授权的群文本发送已验证。目标会话中回读到完整本机发出记录及非零 server_id；发送及随后5秒的前台焦点保持不变。这是单次验证，不保证所有场景或对方已读。不要把适配或研究请求理解为测试消息授权。

## 使用

脚本在本 skill 根目录的 scripts/send/adapter.py。解释器：%LOCALAPPDATA%/wechat2codex/venv/Scripts/python.exe。
使用 Node child_process.spawn，windowsHide: true，参数数组，捕获 stdout/stderr；不弹出控制台。

- inspect：只读检查进程、DLL 哈希、运行中函数字节和虚函数表。
- probe：加载独立 DLL，构造并释放内存文本对象，不进入发送队列。无需改安装文件或重启微信。此模式不会验证送达。
- send --to <准确微信ID> --text-file <UTF-8文件> --draft-id <已批准草稿ID> --experimental：提交该草稿的一次文本。临时文件保留用户原文，传递前不要添加前缀、改写、去空白或改换行。完成后删除本次临时文件。

发送前运行 inspect，再运行 probe。账号进程不唯一时准确选择 --pid，不猜。probe 校验不能替代真实发送验证。
缺少对象或原文时补齐；需要查联系人时使用 scripts/wechat.py chats 的会话列表，不读取无关聊天内容。指定对象和原文后仍须完成 SKILL.md 中的草稿审核。
用户要求测试时，可建议“文件传输助手 + Codex 后台发送测试”，收到明确选择后制作测试草稿，同样经预览和人工批准才发送。当前实现支持 UTF-8 正文最大 3071 字节，准确对象ID最大255字节；超限拒绝，不分拆或截断用户消息。

## 回执与停止

submitted_unconfirmed 仅表示 native 调用返回，不能报告“已发送成功”。通过 scripts/wechat.py read 回读指定会话中新出现的本机发出记录，核对目标、完整文本、时间及可用的状态字段；分开报告“已提交”“本机已记录”和“服务端确认”。没有服务端证据，不声称对方收到。
提交结果不明、超时或回读失败时停止，不自动重试，避免重复发送。批准在 native 调用前即消费，失败也不能重用；先核对回执，确需再发时重新草拟审核。脚本 attempts.jsonl 不包含正文，仅记录目标、正文哈希和状态。
DLL 哈希或运行签名不符时停止，不绕过校验，不降级到点击/键盘发送。新版适配须重新定位。
诊断或发送加载的独立 DLL 留在微信进程中，微信自然退出后失效；不主动卸载有异步回调的 DLL、不重启微信。

## 实现与验证

源代码和固定版本配置位于 scripts/send/native.c、scripts/send/profile.h、scripts/send/profile.json。clang/lld 已在本机编译；二进制只导入 kernel32，无 GUI 自动化 API。
原生发送队列和无捕获回调通过了一次真实群文本验证；持续使用和其他会话场景尚未验证。SEH 能报告同步异常，不能保证捕获异步微信线程异常。执行时遵守用户本次授权的单条消息范围。

## 文件发送（固定版本原生组件）

当前微信 4.1.15.13 的独立文件组件在 scripts/send/file-adapter/，不会覆盖已验证的文本 DLL。已验证运行签名、原生附件对象构造和释放，以及发给文件传输助手的55字节中文名文件：准确文件名和大小、非零 server_id、附件/CDN标识及上传MD5与源文件一致。首轮测试5.5秒内前台焦点未改变；修正版测试期间用户主动切换应用，该轮不作为焦点恒定证据。尚无接收端下载后的SHA256证据；未单独实测大文件、群文件及其他格式。

- adapter.py inspect：只读检查当前进程。
- adapter.py preflight --file <绝对路径>：只读检查文件、路径长度、大小及 SHA256。
- adapter.py probe：构造并释放测试附件对象，不提交队列。
- adapter.py send-file --to <准确微信ID> --file <绝对路径> --draft-id <已批准草稿ID> --experimental：仅在该附件草稿经人工批准后，提交一次普通附件。

保留原文件名，将 UTF-8 文件名及 UTF-16 本地路径交给微信原生附件任务；微信自己生成并转义 XML，不要把预制 XML 传到名称字段。当前实验组件仅接受 1 字节到 100 MiB、UTF-16 路径最多1023码元的单个普通文件；这是组件限制，不是微信官方文件大小上限。发送前制作内容哈希一致的私有快照，供异步上传读取；不要在上传结果不明时删除快照、卸载 DLL 或重试。快照存于 AppData/Local/wechat2codex/private/send/files/。

回读消息必须核对本机发送者、准确会话ID、新时间、附件名称、大小、子类型6、上传附件标识是否存在及非零 server_id。当前数据库附件类型编码为 (6 << 32) | 49；get_message_row 用此编码过滤，XML 使用 get_messages 解压后的 content。上传密钥和 aeskey 只判断是否存在，不输出值。只出现卡片或调用返回，不代表真实文件传输成功；下载后哈希一致才可报告端到端内容验证。需要测试时补齐文件及接收对象，不沿用上次文字消息的授权。

发送不依赖前台窗口。前台监测仅用于诊断，不能作为开始、暂停、重试、选择接收对象的条件；用户切换应用期间，第二次文件上传及服务端回执仍然成功。接收对象始终使用用户指定的准确 ID，不读取当前聊天窗口决定目标。
